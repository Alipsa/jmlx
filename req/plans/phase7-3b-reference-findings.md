## 4. Processor and preprocessing reference

### 4.1 Construction (2026-10-08 decision (a) in force)

Both reference tools construct the processor **directly** (no `AutoProcessor`): the slow
`Qwen2VLImageProcessor` plus `Qwen2TokenizerFast`, with explicit options. The artifacts declare
`Qwen2VLImageProcessorFast`; using the slow PIL implementation is the documented deviation. The
probe wrapper also constructs a `Qwen3VLVideoProcessor` instance via `from_pretrained` *without*
torchvision — this is only to satisfy the processor constructor's non-None `video_processor`
argument (`video_processor=None` is rejected: `TypeError: Received a NoneType for argument
video_processor, but a BaseVideoProcessor was expected`). Without torchvision, 4.57.6 resolves
`BaseVideoProcessor` to a dummy class, so the probe overrides
`check_argument_for_proper_class` for `video_processor` only; image-only behavior is unaffected.

### 4.2 The 4.57.6 slow-processor `size` bug (probed; golden `processor.slow_size_bug`)

`Qwen2VLImageProcessor.__init__` overwrites a valid `size` dict from the config with the
**defaults** `min_pixels = 3136` (56·56) and `max_pixels = 1,003,520` (14·14·4·1280), ignoring
the artifact's declared `size` {shortest_edge 65,536, longest_edge 16,777,216}
(`config_size_ignored: true` in the golden). Both reference tools therefore compensate:
`from_pretrained(dir, min_pixels=65536, max_pixels=16777216)`. The retained (inert) resolved
size dict on the slow path is `{shortest_edge: 3136, longest_edge: 1003520}`. The **planned**
jmlx path is unaffected by this bug: it reads the preprocessor JSON directly and applies the
2026-10-08 effective values (min 65,536, effective max 1,048,576 per decision (b)).

### 4.3 Resolved options (effective for the image path)

`do_resize` true, `resample` BICUBIC, `do_rescale` true with factor 1/255, `do_normalize` true
with mean/std [0.5, 0.5, 0.5], `do_convert_rgb` true, `patch_size` 16, `temporal_patch_size` 2,

### 4.4 Color path (raw PIL → RGB float)

- `convert_to_rgb` = PIL `convert("RGB")`. **Alpha is dropped, never composited**: an RGBA or
  LA image keeps its color channels and loses its alpha. Verified with fixture
  `rgba_8x8.png`: drop-alpha matches the reference, compositing over white does not
  (`drop_alpha matches true, composite_over_white matches false`; LA same).
- **tRNS is never applied** even for palette images. Verified with a palette PNG carrying tRNS
  [0, 128, 200, 255]: the reference output matches plain `convert("RGB")` with the tRNS entry
  dropped (`drop_trns_convert_rgb matches true`).
- **EXIF orientation is applied**: the reference pipeline runs `exif_transpose` before
  resize. Verified with an orientation-6 fixture (90° CW transpose matches; no transpose does
  not). Note the divergence from jmlx-vision's `ImageDecoder`, which ignores EXIF orientation
  (matching the pinned SmolVLM/Idefics3 reference path, not this one); closing the gap for the
  Qwen path is tracked as plan WP9 (`req/plans/phase7-3b-plan.md`).
- jmlx-vision's `ImageDecoder` drops the tRNS chunk before decode in all cases (existing
  behavior, retained).

### 4.5 Resize geometry — `smart_resize` (4.57.6, transcribed verbatim)

`factor = patch_size · merge_size = 32`; all arithmetic is binary64 (Python float):

```python
if max(height, width) / min(height, width) > 200: raise ValueError   # aspect guard
h_bar = round(height / factor) * factor          # note: Python `round` = banker's rounding
w_bar = round(width / factor) * factor
if h_bar * w_bar > max_pixels:
    beta = math.sqrt(height * width / max_pixels)
    h_bar = max(factor, math.floor(height / beta / factor) * factor)   # two sequential divisions
    w_bar = max(factor, math.floor(width / beta / factor) * factor)
elif h_bar * w_bar < min_pixels:
    beta = math.sqrt(min_pixels / (height * width))
    h_bar = math.ceil(height * beta / factor) * factor
    w_bar = math.ceil(width * beta / factor) * factor
```

Probe cross-check: `grid_matches_rederived_smart_resize: True` — the processor's reported
`grid_thw` for both pinned cases equals a from-scratch re-implementation of the above.

### 4.6 Normalization, temporal duplication, patch permutation

- **Order and dtype:** uint8 RGB → resize (BICUBIC) → `× 1/255` → `(x − 0.5) / 0.5`, all in
  float32. Output tensor shape `[num_patches, 3 · 2 · 16 · 16]` = `[N, 1536]`.
- **Temporal duplication:** one image is one frame; it is repeated to 2 identical frames so
  `grid_t = 2 / temporal_patch_size = 1`. Both temporal slots of every patch hold identical
  pixel data.
- **Flatten order** (row-major over these axes): `(t, merged_h, merged_w, merge_h, merge_w,
  c, temporal, patch_row, patch_col)` — i.e. the patch grid grouped into merge blocks, block
  major; innermost axis order `(c, temporal, patch_row, patch_col)` → 1536 = 3·2·16·16. The
  4.57.6 source does this as `reshape` + `transpose(0, 3, 6, 4, 7, 2, 1, 5, 8)`. This ordering
  is load-bearing for the merger and the vision rotary positions (§5, §6).
- **AlphaPolicy (new, additive, `jmlx-vision`):** the reference's `convert("RGB")` semantics are
  "drop alpha, keep source color channels." The existing `ImageDecoder` default
  (`COMPOSITE_OVER_WHITE`, the Pillow-exact integer composite) served 7.3a and is unchanged for
  every existing overload; the new enum value `DROP_ALPHA` implements the reference semantics
  for the Qwen3-VL file→processor path. tRNS is stripped before decode under **both** policies.
  New `ImageDecoder.decode(Path|InputStream, limits, policy)` overloads; `null` policy rejected
  (test). Verified by the §4.4 fixtures and `:jmlx-vision` tests (RGBA/LA drop-vs-composite).

## 5. Vision tower arithmetic (transformers 4.57.6, `modeling_qwen3_vl.py`)

All shapes below for the 2B; the 8B analogue is in §8.4. N = `grid_t · grid_h · grid_w`.

1. **PatchEmbed:** `nn.Conv3d(3, 1024, kernel=[2,16,16], stride=[2,16,16], bias=True)` over the
   view `(-1, 3, 2, 16, 16)` of the flattened patches → `[N, 1024]`
   (checkpoint weight [1024, 3, 2, 16, 16]).
2. **Learned position embedding + interpolation:** `pos_embed` is a learned table
   `[2304, 1024]` = 48×48 grid (`num_position_embeddings` 2304, `num_grid_per_side` 48).
   `fast_pos_embed_interpolate` samples it bilinearly for a (h, w) grid: indices
   `torch.linspace(0, 47, h)` / `linspace(0, 47, w)` (binary64), floor/ceil with ceil clipped
   to 47, weights = fractional parts; result is permuted into the **same merge-block order**
   as the patches (§4.6) and **added** to the patch-embed output. Probed:
   `pos_embed_interpolated` `[N, 1024]`.
3. **Blocks × `depth` (24 for 2B):** pre-norm
   `LayerNorm(1024, eps 1e-6, bias)` → attention → residual; `LayerNorm` → MLP
   (`linear_fc1` 1024→4096 **bias** → `gelu_pytorch_tanh` → `linear_fc2` 4096→1024 **bias**)
   → residual. At each `deepstack_visual_indexes` block (2B: 5, 11, 17) the block's **post
   MLP+residual** output is also routed to the merger list (deepstack, §6.6).
4. **Vision attention:** a single fused `qkv` `Linear(1024 → 3·16·128, bias)`; 16 heads of
   head_dim 64, **no GQA**; **non-causal** full attention over each image, segmented per image
   via `cu_seqlens` (eager/sdpa path: split + per-segment attention; FA2 path: `cu_seqlens`
   passthrough); softmax **upcast to float32**; `o_proj` `Linear(2048 → 1024, bias)`.
5. **Vision rotary (two-axis):** `Qwen3VLVisionRotaryEmbedding(head_dim // 2 = 32, theta
   10000)`. `rot_pos_emb(grid_thw)` assigns each patch a **(row, col) index pair in the
   processor's merge-block order** (merge block major, then the 2×2 in-block position) and
   builds `freqs = cat(row_inv, col_inv)` → `[N, 32]`; `cos/sin = cat((freqs, freqs), -1)` →
   `[N, 64]`. `apply_rotary_pos_emb_vision` upcasts q, k to float32, applies
   `q·cos + rotate_half(q)·sin`, casts back to the input dtype. Probed: `rot_pos_emb`
   `[N, 32]` for both cases.
6. **Merger (final):** the block output, still in merge-block order, is reshaped
   `(…, 2, 2, hidden)` → `LayerNorm(eps 1e-6)` (main merger: `use_postshuffle_norm False` —
   the norm is applied **before** the 2×2 grouping) → `linear_fc1` (1024→4096, bias) →
   `nn.GELU()` (**plain GELU, not the tanh approximation**) → `linear_fc2` (4096→2048, bias)
   → `[merged_rows, 2048]`, `merged_rows = N / 4`. The 2×2 grouping comes from the input
   ordering (the processor's permutation §4.6 + the pos-embed interpolation's permute), not
   from a shuffle inside the merger. Probed: `merger_out` [64, 2048] / [72, 2048].
7. **Deepstack mergers:** `deepstack_merger_list` — 3 `PatchMerger`s for the 2B

### 6.4 MRoPE delta and cache positions

`delta = llm_positions.max() + 1 − len(input_ids)` (`processing_qwen3_vl.py:1011`) — the
negative amount by which the *logical* sequence index exceeds the largest *position value*:

- 256×256: `11max → 25 + 1 − 82 = −56` (= merged-grid max dim 8 − token count 64, algebraically
  equivalent for a single image)
- 64×32: `15max → 16 + 1 − 90 = −60` (= 12 − 72)

**Cache vs. RoPE positions are different counters** (probed decode, 4 steps each):

| case | HF `cache_position` | KV length | RoPE positions (all axes equal after image) |
|---|---|---|---|
| 256×256 | 82, 83, 84, 85 | 83…86 | 26, 27, 28, 29 |
| 64×32 | 90, 91, 92, 93 | 91…94 | 30, 31, 32, 33 |

jmlx must keep these separate: the KV cache slot advances by 1 per token, while the RoPE
position follows the three-axis max + 1 (which coincide with the sequential index only because
the image block's T axis saturates at `st_idx`).

### 6.5 Interleaved MRoPE layout (text decoder)

`mrope_interleaved: true` with `mrope_section [24, 20, 20]` (sum 64 = head_dim/2) and
`rope_theta` 5,000,000. Transcribed from the 4.57.6 source
(`modular_qwen3_vl.py:409-444`, `Qwen3VLTextRotaryEmbedding`):

1. `freqs` is built per axis: for d ∈ {0=T, 1=H, 2=W},
   `freqs[d] = position_ids[d] @ inv_freq` in **float32** (autocast explicitly disabled),
   giving `(3, bs, seq, 64)`.
2. `apply_interleaved_mrope(freqs, mrope_section)` starts from the **T row** and overwrites
   in place:
   ```python
   freqs_t = freqs[0]                                  # T owns every frequency initially
   for dim, offset in enumerate((1, 2), start=1):      # H, then W
       length = mrope_section[dim] * 3                 # 60 for both
       idx = slice(offset, length, 3)
       freqs_t[..., idx] = freqs[dim, ..., idx]
   ```
   i.e. H writes frequency indices `1, 4, 7, …, 58` (20 frequencies) and W writes
   `2, 5, 8, …, 59` (20); everything else stays T (24). Final per-frequency owner for f ∈
   0..63: `f % 3 == 0 → T`, `f % 3 == 1 → H` (f < 60), `f % 3 == 2 → W` (f < 60), and
   `f ∈ 60..63 → T` — a T-starting round-robin `T H W T H W …` with a terminal run of four T
   frequencies (the source docstring: chunked `[TTT…HHH…WWW]` → interleaved
   `[THTHWHTHW…TT]`).
3. `emb = cat((freqs_t, freqs_t), -1)` → 128; `cos = emb.cos() · attention_scaling`,
   `sin = emb.sin() · attention_scaling` (scaling = 1.0 for `rope_type: default`), computed in
   float32 and cast back to the input dtype before use in the attention rotate-half op.

### 6.6 DeepStack timing (text side)

After the full decoder stack, for `i in 0..len(deepstack_visual_embeds)−1` (2B: 3 levels), the
vision feature `deepstack_visual_embeds[i]` (level `i` = features from vision block
`deepstack_visual_indexes[i]`, each `[merged_rows, hidden]`) is **added into the hidden states
at exactly the image-token positions only** — masked clone + add + write-back
(`modeling_qwen3_vl.py` lines ~862–883), after text layer `i`. No effect on text-only tokens;

  tokens differ, which is expected (different runtime, checkpoint, precision).
- The prefill `top20` entries are ordered `[id, score]` here (the 2B HF probe recorded
  `[score, id]`) — recorded to avoid confusion when the two goldens are read side by side.

**Kernel breakdown** (8B as instantiated by mlx-vlm 0.3.9, golden `model.kernels`): vision —
116 `nn.Linear` (all BF16), 1 Conv3d, 1 Embedding, 4 PatchMerger, 58 LayerNorm, 31 GELU,

**Scope of the 8B evidence.** Per the plan, this is the compatibility/provenance gate for the
MLX affine quantized path — **not a parity claim** (golden `model.no_parity_claim`:

fixed by this evidence: packed affine quantized linears (U32 `[out, in/8]` + BF16
